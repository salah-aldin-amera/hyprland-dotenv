# hyprland-dotenv

Personal dotfiles for an Arch Linux + Hyprland (Wayland) desktop, with a
one-command installer that brings a fresh machine up to the same setup.

One config tree serves every machine. What differs between boxes is isolated
into two small layers — a **machine class** (`pc` or `laptop`) and a **host
file** (per-box monitors and GPU) — so nothing machine-specific leaks into the
shared config.

## Quick start

On a fresh Arch install:

```sh
git clone https://github.com/salah-aldin-amera/hyprland-dotenv.git
cd hyprland-dotenv
./install.sh
```

It asks whether the machine is a **pc** or a **laptop**, then installs
packages, links configs, and enables services. Re-running is safe — anything
it replaces is copied to `~/.dotfiles-backup/<timestamp>/` first.

```sh
./install.sh --machine laptop        # skip the prompt
./install.sh --profile dev           # core + development tooling
./install.sh --profile full          # + browsers, creative, media
./install.sh --dry-run               # print every action, change nothing
./install.sh --configs-only          # relink configs, skip packages
./install.sh --help
```

Always worth running `--dry-run` first on a machine you care about.

### Profiles

| Profile | Contents                                                    |
| ------- | ----------------------------------------------------------- |
| `core`  | Usable Hyprland desktop: compositor, bar, terminal, launcher, portals, audio, fonts, file manager |
| `dev`   | core + editors, languages, containers, databases, CLI tools  |
| `full`  | dev + browsers, creative suite, messaging, media, downloaders |

The machine list (`pc.list` or `laptop.list`) is always applied on top.

## Machine classes

Selected at install time and recorded in `~/.config/hypr/local.lua`.

| | `pc` | `laptop` |
| --- | --- | --- |
| Monitors | explicit layout from host file | auto-detect |
| Input | ydotool keyboard-driven mouse, keyd mouse remap | touchpad + 3-finger workspace swipe |
| Backlight | — | `XF86MonBrightness*` → brightnessctl |
| Lid | — | lock on close |
| Idle | lock at 15 min, displays off, never suspends | dim 2.5 min, lock 5 min, suspend 30 min |
| Waybar | UPS load + UPS battery | battery, backlight, network, power profile |
| Extras | rkvm **server**, apcupsd | rkvm **client**, power-profiles-daemon |

Switch a machine over by re-running `./install.sh --machine laptop`.

## Hyprland config

Hyprland 0.55+ reads a **Lua** config, and this repo uses it — real variables,
loops, and `require`, rather than repeated `source =` lines. `hyprland.lua` is
machine-agnostic; the last thing it does is pull in the two specific layers:

```
dotfiles/conf/hypr/
  hyprland.lua              # shared: look, binds, rules, autostart
  local.lua                 # GENERATED by install.sh, gitignored
  modules/
    workspaces.lua          # workspace binds
    windows.lua             # move / resize binds
    mouse-bindings.lua      # ydotool mouse keys (required by pc only)
  machine/
    pc.lua                  # desktop: devices, no backlight
    laptop.lua              # touchpad, gestures, backlight, lid
  hosts/
    salahaldin-pc.lua       # 4 monitors, dual-GPU pin, kdeconnect, nextcloud
    salahaldin-sgsoft.lua   # single GPU, auto monitors
  hyprlock.conf hypridle.conf hypridle-laptop.conf
  hyprpaper.conf hyprlauncher.conf
```

`local.lua` is the only per-machine file, and it is deliberately **not**
tracked — every box would otherwise fight over the same two lines:

```lua
return {
    machine = "pc",
    host    = "salahaldin-pc",
}
```

A missing host file is not an error: monitors fall back to auto-detect, so a
brand-new machine boots to a working session before you pin its layout. To add
a box, drop in `hosts/<hostname>.lua` and re-run the installer.

### Adding a new machine

1. `./install.sh` — pick pc or laptop, get a working desktop immediately.
2. `hyprctl monitors all` to read the real outputs.
3. Create `dotfiles/conf/hypr/hosts/$(uname -n).lua` with `hl.monitor()` calls.
4. `./install.sh --configs-only` to regenerate `local.lua` so it picks the host
   file up.

## Launcher: hyprlauncher

[hyprlauncher](https://github.com/hyprwm/hyprlauncher) replaces rofi and wofi
entirely — one native Hyprland tool instead of two GTK launchers with a dozen
themes between them. It runs as a daemon (`hyprlauncher -d` from autostart) so
`SUPER + SPACE` toggles an already-warm process.

Type a prefix to switch what you are searching:

| Prefix | Searches | Notes |
| ------ | -------- | ----- |
| *(none)* | applications | frequency-ranked |
| `.` | unicode / emoji | copies to clipboard |
| `=` | math | via libqalculate, e.g. `= 17 * 3 + 2` |
| `'` | fonts | copies the family name |

It also covers what rofi was doing for clipboard history, through its dmenu
mode (`hyprlauncher -m`).

Appearance comes from the hyprtoolkit theme, not from `hyprlauncher.conf`.

## Waybar

Module *definitions* live once in `waybar/modules.jsonc`. The per-machine files
(`config-pc.jsonc`, `config-laptop.jsonc`) only pick which modules appear, and
pull the definitions in with waybar's own `include`. install.sh links the right
one to `config.jsonc`, so there is no duplicated module config to keep in sync.

## The desktop stack

| Role | Tool |
| ---- | ---- |
| Compositor | Hyprland (Lua config) |
| Launcher / picker | hyprlauncher |
| Bar | Waybar |
| Terminal | kitty |
| Lock / idle | hyprlock + hypridle |
| Wallpaper | hyprpaper |
| Screenshot / picker | hyprshot + hyprpicker |
| Notifications | dunst |
| Clipboard | cliphist + wl-clipboard |
| Polkit agent | hyprpolkitagent |
| Portals | xdg-desktop-portal-hyprland (+ gtk) |
| Audio | PipeWire + WirePlumber |
| Files | Dolphin (KDE apps, no full Plasma session) |

`xdg-desktop-portal-wlr` is deliberately **not** installed — it competes with
the Hyprland portal for the ScreenCast interface and breaks screen capture.

## One-time extras

These are not in `install.sh` — they are interactive, or one-shot per machine,
and do not belong in a re-runnable script. Carried over from the retired
`scripts/install-apps.sh` (still in git history).

```sh
# Oh My Zsh (prompts, and rewrites ~/.zshrc)
sh -c "$(curl -fsSL https://raw.githubusercontent.com/ohmyzsh/ohmyzsh/master/tools/install.sh)"

# PostgreSQL cluster init — only after installing --profile dev
sudo -u postgres initdb --locale=C.UTF-8 --encoding=UTF8 -D /var/lib/postgres/data
sudo systemctl enable --now postgresql.service

# Bluetooth, if the machine has it
sudo systemctl enable --now bluetooth.service
```

## rkvm

One keyboard and mouse across machines. `salahaldin-pc` runs `rkvm-server`
(the box with the physical keyboard); other machines run `rkvm-client`.
Switch input with `left-alt + left-ctrl`.

Client and server must be the **same version**. On a machine without Rust and
base-devel, build the package on the server and ship it over rather than
installing a toolchain:

```sh
git clone https://aur.archlinux.org/rkvm.git && cd rkvm && makepkg -f
scp rkvm-*.pkg.tar.zst <client>:/tmp/
ssh <client> 'sudo pacman -U /tmp/rkvm-*.pkg.tar.zst'
```

The client needs `certificate.pem` only — `key.pem` never leaves the server.
The certificate is pinned to the server's IP (SAN), so `client.toml` must use
that IP, not a hostname.
